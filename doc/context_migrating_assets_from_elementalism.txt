MIGRATING ASSETS FROM ELEMENTALISM TO ZD_DAF
=============================================
Context document for AI-assisted development.
Covers the full migration process learned from migrating seaweed, rocks, chains,
shackles, floor skeletons, barrel, tablet, stalactite, PumpJack, and WaterBossHead
(ElderBrain).


SOURCE LOCATION
---------------
Elementalism source lives at:
  c:\dev\zd_daf\elementalism\

Sprite subdirs within elementalism:
  sprites/decorations/    rock/prop placeholder sprites (CDRA, PJKA etc.)
  sprites/Gibbet/         shackle static sprites (SHAO, SHCL)
  sprites/q3a/            skeleton sprites (NADA)
  sprites/Models/         animated model sprites (NO3D, NB3D etc.)
  sprites/waterboss/      waterboss full-rotation sprites (WBSS)

Actor source:   elementalism/actors/Clay_Models.txt   (DECORATE syntax)
Modeldef source: elementalism/models/Clay_Modeldef.txt
PumpJack is a special case with its own files:
  elementalism/actors/PumpJack.txt  (actor)
  elementalism/models/PumpJack.txt  (MODELDEF)
  elementalism/actors/PumpJack.gl   (GLDEFS for PBR materials)

Monsters live in elementalism/actors/<MonsterName>.txt and may be SPRITE-ONLY
(no model, no MODELDEF). Check by searching elementalism/models/*.txt and the
MODELDEF lump for the class name -- if absent, it is sprite-only.
WaterBoss.txt is an example: WaterBossHead is purely sprite-based.


WHAT TO MIGRATE (CHECKLIST)
----------------------------
FIRST: determine if the actor is model-based or sprite-only.
  - Model-based: has an entry in elementalism/models/*.txt or MODELDEF lump.
  - Sprite-only: no MODELDEF entry. Only sprites and a ZScript class are needed.

For MODEL-BASED actors, you need ALL of the following or it will fail:
  1. Model file(s)      .md3 or .obj geometry file
  2. Skin file(s)       .png or .jpg textures for each surface
  3. Sprite lumps       .png files for every sprite name+frame used in States {}
  4. MODELDEF entry     Model block with Scale, Skin/GLDEFS, FrameIndex lines
  5. ZScript actor      class definition with Default and States
  6. DoomEdNum          entry in zd_daf/MAPINFO DoomEdNums block
  7. GLDEFS (if PBR)    .gl file with material texture blocks, included in GLDEFS

For SPRITE-ONLY actors:
  1. Sprite lumps       ALL .png files from the elementalism sprite folder for this actor
  2. ZScript actor      class definition with Default and States
  3. DoomEdNum          entry in zd_daf/MAPINFO DoomEdNums block

If the original skin file cannot be found (e.g. gibbet_drk.jpg), substitute the
nearest available alternative and note it in a comment in the modeldef.


FILE DESTINATIONS IN ZD_DAF
-----------------------------
  Model .md3/.obj        ->  zd_daf/models/<name>.md3        (flat, no subdirs)
  Single-surface skins   ->  zd_daf/models/skins/<name>.png
  Multi-surface skins    ->  zd_daf/models/skins/<foldername>/<name>.png
                             (folder name must match MD3 embedded shader strings)
  Normal maps            ->  zd_daf/materials/normalmaps/<name>.png
  Specular maps          ->  zd_daf/materials/specularmaps/<name>.png
  Sprite lumps           ->  zd_daf/sprites/<groupname>/      (subdirectory)
  MODELDEF               ->  zd_daf/models/defs/<category>.modeldef
  ZScript actor          ->  zd_daf/actors/<category>.zs
  GLDEFS file            ->  zd_daf/actors/<name>.gl  (included in zd_daf/GLDEFS)
  DoomEdNum              ->  zd_daf/MAPINFO DoomEdNums block

Categories and their files:
  plants.modeldef / plants.zs              -- seaweed, anemone, organic decor
  dungeon_props.modeldef / dungeon_props.zs -- rocks, chains, shackles, props
  architecture.modeldef / architecture.zs  -- structural/Giger models
  (create new .modeldef + .zs for genuinely new categories)

New .modeldef files must be added to zd_daf/MODELDEF via #include.
New .zs files must be added to zd_daf/zscript.zs via #include.
New .gl files must be added to zd_daf/GLDEFS via #include.


FILE NAMING CONVENTION
----------------------
All model and skin filenames in zd_daf/ must be lowercase snake_case.
Convert CamelCase names from elementalism on copy:

  SmallOrnamentalPlant1.obj  ->  small_ornamental_plant_1.obj
  Tablet.obj                 ->  tablet.obj
  BB_chain_dark_diffuse.png  ->  bb_chain_dark_diffuse.png

EXCEPTION: Multi-surface MD3 skin folders must preserve the exact folder name
embedded in the MD3 shader strings (see MULTI-SURFACE MD3 section below).
Example: PumpJack MD3 embeds "models/skins/pumpjack/..." so the folder must be
named "pumpjack" not "pump_jack". Check embedded strings before renaming.

ZScript class names use CamelCase as required by the language.
MODELDEF block names match the ZScript class name exactly (CamelCase).
DoomEdNum entries use the ZScript class name (CamelCase).


SPRITE NAMING CONVENTION
------------------------
GZDoom/UDB sprite lumps follow the format:  <SPRT><FRAME><ROTATION>.png
  SPRT  = 4-character sprite name (e.g. CDRA, NO3D, NADA, PJKA, WBSS)
  FRAME = single letter A-Z
  ROT   = rotation index

Rotation values:
  0        = no rotation (single image, all angles)
  1-8      = 8-rotation sprite (standard Doom)
  1-9,A-G  = 16-rotation sprite (GZDoom extension; A=10, B=11, ... G=16)

Example: CDRAA0.png  ->  sprite=CDRA, frame=A, rotation=0 (no rotation)
Example: WBSSA1.png  ->  sprite=WBSS, frame=A, rotation=1 of 16

The ZScript States block references the 4-char sprite name and frame letter only:
  CDRA A -1;    <- displays CDRAA0.png (no rotation)
  WBSS A 1;     <- displays WBSSA1..WBSSAG depending on viewing angle (16 rotations)

UDB requires one sprite PNG per 4-char sprite name used in States. If only a
single placeholder exists (e.g. only PJKAA0.png, but States uses PJKA/PJKB/PJKC/PJKD),
copy PJKAA0.png as PJKBA0.png, PJKCA0.png, PJKDA0.png. All are invisible placeholders.

Do NOT substitute TNT1 for missing sprites -- it hides the model from the UDB thing browser.

Commonly migrated sprite groups and their elementalism source locations:
  CDRA/CDRB/CDRC/CDRD  ->  elementalism/sprites/decorations/  (rocks)
  PJKA/PJKB/PJKC/PJKD ->  elementalism/sprites/decorations/  (pump jack, only PJKAA0 exists)
  NADA                 ->  elementalism/sprites/q3a/           (skeletons)
  SHAO / SHCL          ->  elementalism/sprites/Gibbet/        (shackles static)
  NO3D / NB3D etc.     ->  elementalism/sprites/Models/        (animated models)
  BAR1                 ->  elementalism/sprites/...            (barrel)
  WBSS                 ->  elementalism/sprites/waterboss/     (elder brain, 16-rotation)


MODELDEF: TWO STYLES
--------------------
ZD_DAF uses two MODELDEF path styles. Choose based on where skins come from.

STYLE 1 -- Path directive (skins inside models/skins/):
  Path "models"
  Model 0 "seaweed.md3"
  Skin 0 "skins/seaweed.png"
Used by: plants.modeldef, architecture.modeldef

STYLE 2 -- Full PK3-root paths (skins from textures/ or mixed sources):
  Model 0 "models/rocks1.md3"
  Skin 0 "textures/zoon_tex/ZKHXRK03.png"
Used by: dungeon_props.modeldef

Use Style 2 whenever the skin comes from zd_daf/textures/ rather than
zd_daf/models/skins/, because the Path directive would also apply to Skin paths.

MULTI-SURFACE MD3 (no Skin lines in MODELDEF):
  Model 0 "models/pump_jack.md3"
  Scale 50 50 50
  ... FrameIndex lines ...
  (no Skin lines)
GZDoom resolves skins from the paths embedded in the MD3 shader strings.
GLDEFS material texture blocks then overlay PBR materials on top.
See GLDEFS MATERIAL BLOCKS section below.

Standard flags:
  DONTCULLBACKFACES  -- always include for thin geometry (chains, foliage)
  USEACTORPITCH      -- include for all props/models
  USEACTORROLL       -- include alongside USEACTORPITCH for zd_daf convention

Do NOT copy zero-offset lines ("offset 0 0 0") from elementalism; they are implicit.
Copy Scale directly from elementalism. Variants of the same mesh may differ.


ANIMATED MODELS: FRAMEINDEX
----------------------------
Elementalism sprite-driven animation maps sprite frames to MD3 keyframes:
  FrameIndex NO3D A 0 0    <- sprite NO3D frame A = MD3 frame 0
  FrameIndex NO3D B 0 1
  ...
  FrameIndex NB3D A 0 26   <- continues from where NO3D left off
  ...

Copy ALL FrameIndex lines verbatim from the source modeldef.
Count frames carefully -- variants of the same mesh may use different frame counts:
  seaweed1: NO3D A-Z (0-25) + NB3D A-O (26-40) = 41 frames
  seaweed2/3: NO3D A-Z (0-25) + NB3D A-N (26-39) = 40 frames
  shackles: NO3D A-Z + NB3D A-Z + NC3D A-Z + ND3D A-W = 101 frames
  pump jack: PJKA A-Z + PJKB A-Z + PJKC A-Z + PJKD A = 80 frames (0-79)

The actor States block must loop through the same sprite sequences:
  Spawn:
      NO3D ABCDEFGHIJLKMNOPQRSTUVWXYZ 2;
      ...
      Loop;

Note: Some elementalism actors have transposed letters (e.g. "HIJLK" instead of
"HIJKL") or duplicate/skipped MD3 frame indices. Copy verbatim to preserve the
original animation rhythm. Correcting these would change visual behaviour.
Known PumpJack anomalies:
  PJKA L -> MD3 frame 12  (frame 11 skipped in source)
  PJKB I and PJKB J both -> MD3 frame 35  (frame 36 skipped)


GLDEFS MATERIAL BLOCKS (PBR: normal maps + specular)
------------------------------------------------------
Some models (e.g. PumpJack) use GLDEFS to apply normal maps and specular maps
to each surface. This is separate from the MODELDEF skin system.

To migrate a model with GLDEFS:
1. Copy normal map PNGs to zd_daf/materials/normalmaps/
2. Copy specular map PNGs to zd_daf/materials/specularmaps/
3. Create zd_daf/actors/<name>.gl with material texture blocks
4. Add #include "actors/<name>.gl" under "// Models" in zd_daf/GLDEFS

Format of a material block:
  material texture "models/skins/pumpjack/walking_beam.png"
  {
      normal "materials/normalmaps/walking_beam_norm.png"
      specular "materials/specularmaps/spec_thing.png"
      specularlevel 0.5
      glossiness 1.0
      disablefullbright
  }

CRITICAL: The path in "material texture "..."" must exactly match the skin path
that GZDoom resolves for that surface. For multi-surface MD3s this is the path
embedded in the MD3 shader strings. If it doesn't match, the PBR override is silently
ignored (flat shading only -- functional but not enhanced).

Omitting GLDEFS entirely is acceptable for an initial migration; it gives flat
shading only. Add GLDEFS as a second pass once the model is confirmed working.


ZSCRIPT ACTOR PATTERNS
-----------------------

MONSTER / CREATURE (sprite-only, floating, illithid-type):
  class ElderBrain : Actor
  {
      Default
      {
          //$Category "Monsters/Illithids"
          //$Title "Elder Brain"
          Radius 70;
          Height 130;
          +NOCLIP;
          +SHOOTABLE;
          +NOGRAVITY;
          +ROLLSPRITE;
          +ROLLCENTER;
          +FLOATBOB;
          +DONTTHRUST;
          +FORCEXYBILLBOARD;
          +COUNTKILL;
          +NORADIUSDMG;
          FloatBobPhase 0;
          FloatBobStrength 1.0;
          Species "Illithid";
          DamageFactor "Ice", 0.5;
          DamageFactor "BFGSplash", 0.15;
          Health 1000000;
      }
      States
      {
      Spawn:
          WBSS A 1 A_RadiusThrust(5000, 256, RTF_NOTMISSILE, 64);
          Loop;
      Death:
          TNT1 A 0;
          Stop;
      }
  }

  Notes on monster migration:
  - DECORATE "ACTOR Foo { ... }" becomes "class Foo : Actor { Default { ... } States { ... } }"
  - Add semicolons after every property/flag line.
  - Drop Species from the original if it refers to a boss-specific type not in zd_daf
    (e.g. "WBoss" -> "Illithid" to match zd_daf's species grouping).
  - Drop DamageFactor entries for custom damage types not defined in zd_daf
    (e.g. "WBossDamage"). Keep standard types: "Ice", "BFGSplash", "Fire", etc.
  - Drop ActiveSound / SeeSound / DeathSound if the sound is not migrated.
  - Simplify Death/Pain states if they spawn projectile actors (BloodBoop,
    BossNeckMlem, etc.) that are not being migrated. Replace with Stop.

STATIC MODEL (no animation):
  class RocksDark1 : Actor {
      Default {
          //$Category "Models/Rocks"
          //$Title "RocksDark1"
          Radius 8;
          Height 64;
          +SOLID
          +NOGRAVITY
      }
      States {
          Spawn:
              CDRA A -1;
              Stop;
      }
  }

ANIMATED MODEL:
  class Seaweed1 : Actor {
      Default {
          //$Category "Models/Plants"
          //$Title "Seaweed1"
          Radius 8;
          Height 64;
          -SOLID
          +NOGRAVITY
      }
      States {
          Spawn:
              NO3D ABCDEFGHIJKLMNOPQRSTUVWXYZ 4;
              NB3D ABCDEFGHIJKLMNO 4;
              Loop;
      }
  }

SKIN VARIANT SUBCLASS (inherits mesh + states, overrides only $Title):
  class RocksBrown1 : RocksDark1 { Default { //$Title "RocksBrown1"
  } }

  CRITICAL: The closing "} }" must be on the NEXT LINE after the //$Title comment.
  The "//" comment swallows everything to end-of-line, including any "} }" on the
  same line, causing a ZScript parse error ("Expected a token").

  Skin variants also need their own MODELDEF blocks (cannot inherit MODELDEF).
  The MODELDEF block name must match the subclass name exactly.

LARGE ENVIRONMENT PROP (far-distance culling prevention):
  Default {
      RenderRadius 2500;
      +NOGRAVITY
  }

FLAG TRANSLATION FROM ELEMENTALISM DECORATE:
  -solid      ->  omit +SOLID  (or explicitly -SOLID)
  +nogravity  ->  +NOGRAVITY
  Add +NODAMAGE +NOTARGET for fully inert decorative props.

ZSCRIPT CLASS NAME RULES:
  - Cannot start with a digit.  "3X_chain_straight" -> "Chain3xStraight"
  - Use CamelCase throughout.


MULTI-SURFACE MD3
-----------------
When an MD3 has multiple surfaces (e.g. PumpJack with 7 surfaces), each surface
has an embedded shader string naming its skin texture path. GZDoom resolves these
paths directly from the PK3, so:

1. The skin files must exist at EXACTLY the paths embedded in the MD3.
   To find out what paths the MD3 embeds, open it in a hex editor and search for
   "models/skins/" -- the shader strings are plain ASCII.

2. Do not rename the skin folder if it would break the embedded path.
   Example: PumpJack MD3 embeds "models/skins/pumpjack/walking_beam.png"
   so the folder must be "pumpjack/" not "pump_jack/".
   GZDoom on Windows is case-insensitive, but the exact slug must match.

3. MODELDEF needs no Skin lines for multi-surface MD3s -- just Model 0 + FrameIndex.

4. If GLDEFS material texture blocks are provided, their "material texture "..."" path
   must also match the embedded shader string exactly.

5. If you later want to override the embedded skins via MODELDEF Skin N lines,
   the surface index N corresponds to the order of surfaces in the MD3 file
   (requires checking in Blender or a MD3 viewer).


MULTI-SKIN VARIANTS (same mesh, different skins)
-------------------------------------------------
When the same mesh is used with multiple skins, create:
  - One base actor class with the primary skin
  - Subclasses for each variant, each with its own $Title
  - A separate MODELDEF block per variant (pointing to the correct Skin path)
  - A DoomEdNum per variant

Name the classes to describe the skin's visual appearance, not a generic "_2/_3" suffix:
  RocksDark1   -- dark cracked stone (ZKHXRK03)
  RocksBrown1  -- brown earthy grain (SLROCK1)
  RocksBlack1  -- near-black obsidian (SLROCK22)
  RocksGreen1  -- mossy green (ds_gras1)

Rock skins available in zd_daf/textures/:
  textures/zoon_tex/ZKHXRK03.png             dark cracked stone
  textures/aa_tex/SLROCK1.png                brown earthy grain
  textures/elementalism_tex/SLROCK22.png     near-black obsidian
  textures/darksouls_tex/ds_gras1.jpg        mossy green


UDB CATEGORY BROWSER ($Category)
----------------------------------
The //$Category comment controls the folder in UDB's thing browser.
Use existing categories for consistency:
  "Models/Rocks"       -- rocks, stalactites, cave geometry
  "Models/Plants"      -- seaweed, anemone, organic decor
  "Models/Props"       -- barrel, tablet, pump jack, furniture
  "Models/Chains"      -- chains, shackles
  "Monsters/Illithids" -- mind flayers, elder brain, intellect devourer, etc.

Moving to a different category only requires changing $Category in the ZScript actor.

COMMON MISTAKES
---------------
1. Missing sprite lumps -- UDB: "Unable to find sprite lump CDRAA used by actor..."
   Fix: find and copy the actual .png sprite files from elementalism/sprites/
   Do NOT substitute TNT1 -- it hides the model from the UDB thing browser.
   If only one sprite PNG exists for a multi-sequence animated model (e.g. only PJKAA0),
   copy it as placeholders for each additional sprite name (PJKBA0, PJKCA0, PJKDA0).

2. Wrong model path -- leaving "Models/" prefix from elementalism.
   Fix: Style 1 uses Path "models" + relative name; Style 2 uses full "models/name.md3"

3. $Title comment swallows closing braces in subclass one-liners.
   BROKEN:  class Foo : Bar { Default { //$Title "Foo" } }
   CORRECT: class Foo : Bar { Default { //$Title "Foo"
            } }

4. Skin variant subclass has no MODELDEF block -- renders with wrong/parent skin.
   Fix: every subclass needs its own Model <ClassName> { ... } block in the modeldef.

5. Missing FrameIndex entries -- model loads but is frozen on frame 0.
   Fix: copy ALL FrameIndex lines from the source modeldef for that model.

6. Actor uses DECORATE syntax (no "class", no semicolons) -- ZScript compile error.
   Fix: convert to ZScript class syntax.

7. Class name starts with a digit -- ZScript compile error.
   Fix: prefix with a word, e.g. "3X_chain" -> "Chain3x".

8. Omitting DONTCULLBACKFACES for thin/flat geometry (chains, foliage).
   Fix: add DONTCULLBACKFACES to the MODELDEF entry.

9. Forgetting to add DoomEdNum -- actor doesn't appear in UDB Things browser.
   Fix: add entry to MAPINFO DoomEdNums block.

10. CamelCase filename for model or skin file.
    Fix: rename to snake_case and update all MODELDEF paths referencing it.
    Search all .modeldef files for the old name before renaming.

11. Multi-surface MD3 skin folder name doesn't match embedded shader strings.
    Symptom: UDB/GZDoom reports "unable to load skin models\skins\<name>\..."
    Fix: rename the skin subfolder to match what the MD3 embeds exactly.
    Use a hex editor to read the embedded shader strings if unsure.

12. GLDEFS .gl file created but not included in zd_daf/GLDEFS.
    Symptom: PBR materials silently not applied (flat shading only, no error).
    Fix: add #include "actors/<name>.gl" under "// Models" in zd_daf/GLDEFS.

13. Sprite-only actor treated as model-based -- time wasted searching for a MODELDEF.
    Fix: grep elementalism/models/*.txt and MODELDEF for the class name first.
    If no match: it is sprite-only. Just copy sprites, write ZScript class, add DoomEdNum.

14. Monster Death state spawns actors not present in zd_daf (custom projectiles,
    boss parts, etc.) -- ZScript compile error or broken runtime behaviour.
    Fix: strip the Death state down to TNT1 A 0; Stop; for the initial migration.
    Flesh it out later once the dependent actors are also migrated.

15. Species "WBoss" or other elementalism-specific species not used in zd_daf.
    Fix: change to "Illithid" for illithid-type creatures (controls friendly-fire
    grouping). Check existing actors in zd_daf/actors/ for the correct Species string
    for the category you're targeting.

16. DamageFactor for custom damage types (e.g. "WBossDamage") -- the type doesn't
    exist in zd_daf, causing a silent no-op or compile warning.
    Fix: drop non-standard DamageFactor lines. Keep only standard GZDoom types
    ("Ice", "Fire", "BFGSplash", etc.).
